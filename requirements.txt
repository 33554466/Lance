# Home AI Appliance — Python dependencies
#
# These are deliberately loose: this file says WHAT the appliance needs.
# requirements.lock.txt says exactly what was installed when it last worked,
# and that is what you rebuild from:
#
#     pip install -r requirements.lock.txt
#     pip install --no-deps 'openwakeword==0.6.0'
#
# The lock file used to be in .gitignore, which is why it went fifteen days
# stale and fourteen packages short — every dependency of the printer,
# semantic recall and media playback was missing from it. It is tracked now.
# Re-freeze whenever you add something: ./install.sh writes a .new and shows
# you the diff rather than overwriting it behind your back.

# --- orchestrator ---
fastapi>=0.110
uvicorn[standard]>=0.29
websockets>=12.0
PyYAML>=6.0
# python-dotenv is NOT here. It was declared for a year and never imported —
# which meant the README's "put the key in .env, then run uvicorn by hand"
# never worked: systemd loaded it via EnvironmentFile, a terminal did not.
# core/provider.py now reads .env itself, in six lines, as the last of three
# fallbacks behind the systemd credential and the environment.

# --- provider ---
anthropic>=0.40

# --- audio capture / playback ---
sounddevice>=0.4.6
numpy>=1.26,<3

# --- wake word ---
# openWakeWord is NOT listed here, and that is deliberate.
#
# It declares tflite-runtime as a hard dependency on Linux, but no
# tflite-runtime wheels exist for Python 3.12 — which is exactly what
# Ubuntu 24.04 ships. pip therefore fails the whole install.
#
# We only ever use openWakeWord's ONNX backend (see audio/listener.py,
# inference_framework="onnx"), so tflite is dead weight. install.sh
# installs it with --no-deps and its five real runtime dependencies are
# listed here instead:
onnxruntime>=1.17
tqdm>=4.64
scipy>=1.11
scikit-learn>=1.3
requests>=2.31

# --- endpointing ---
# Nothing to install. Silero VAD runs from the ONNX model that openWakeWord
# already ships, driven through openwakeword.vad.VAD.
#
# The obvious choice — the `silero-vad` package — imports torchaudio at
# module level, which drags in PyTorch. pip then resolves torchaudio from
# PyPI (a CUDA build) even when torch came from the CPU index, and you get a
# CPU torch beside a CUDA torchaudio that cannot find libcudart. Dropping
# both saves ~200 MB and removes that failure mode entirely.

# --- speech to text ---
faster-whisper>=1.0.3

# --- speech synthesis ---
piper-tts>=1.2.0

# --- receipt printer (MUNBYN ITPP047, Epson TM-m30-II ESC/POS) ---
# python-escpos talks libusb directly rather than through CUPS: no print
# queue, no spooler, no job that silently sits in a "processing" state for
# an hour. pyusb is its transport and is listed explicitly so a rebuild
# cannot resolve without it.
pyusb>=1.2.1
python-escpos>=3.0

# --- media playback ---
# yt-dlp searches YouTube and resolves stream URLs; mpv (an apt package, see
# install.sh) plays them. Kept LOOSE on purpose, and pinned in the lock file:
# yt-dlp breaks whenever YouTube changes, so the floor here is a floor, not a
# target. Ubuntu's apt package is years behind and fails extraction on
# everything — install it in this venv, not with apt.
#
# mpv finds it through --script-opts=ytdl_hook-ytdl_path, which core/media.py
# sets explicitly, because a systemd user service's PATH does not include
# this venv's bin directory.
yt-dlp>=2025.1.1

# --- semantic recall ---
# ONNX sentence embeddings. Chosen over sentence-transformers specifically
# because that pulls PyTorch, which was removed from this project on purpose
# (see the VAD note above). fastembed rides on onnxruntime, which is already
# here for the wake word, and adds four small pure-Python/Rust packages.
fastembed>=0.4
